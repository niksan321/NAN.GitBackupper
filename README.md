# SysTrayGitBackupper

Настольное приложение для **Windows**, которое работает в **системном трее** и по расписанию создаёт **локальные резервные копии** репозиториев с облачных Git-провайдеров. Список репозиториев запрашивается через API провайдера, затем выполняется клонирование и обновление через установленный **Git** (HTTPS, токен доступа).

## Возможности

- **Несколько профилей бэкапа** — для каждого задаются провайдер, учётные данные, корневой каталог бэкапа и имя профиля; рабочие клоны лежат в подпапке с именем профиля.
- **Провайдеры**: GitHub, GitLab, Bitbucket, а также **другие** инстансы с **GitLab-совместимым API** (базовый URL задаётся в настройках профиля).
- **Расписание** — интервал между проходами бэкапа и таймаут операций настраиваются отдельно для каждого профиля.
- **Выбор репозиториев** — можно ограничить набор репозиториев и указать **ветку** для каждого из них.
- **Параллельная обработка** — число одновременно обрабатываемых репозиториев ограничивается (в разумных пределах, с учётом числа логических процессоров).
- **Очистка каталога бэкапа** (опционально) — удаление подпапок, не относящихся к текущему списку выбранных репозиториев, перед синхронизацией.
- **Архив после прохода** (опционально) — создание ZIP всего каталога бэкапа профиля с настраиваемым уровнем сжатия.
- **Общие настройки приложения**: автозапуск, старт свёрнутым, уведомления, длительность всплывающих сообщений, язык интерфейса (в т.ч. русский и английский), звук при ошибке, подтверждение удаления и др.

## Требования

- **ОС**: Windows (целевая платформа — `net8.0-windows`, WPF).
- **.NET SDK 8** — для сборки из исходников.
- **Git** — должен быть установлен и доступен в `PATH` (операции клонирования и обновления выполняются через клиент Git).

## Сборка и запуск

Из корня репозитория:

```bash
dotnet build Src/SysTrayGitBackupper.sln -c Release
```

Исполняемый файл: `Src/SysTrayGitBackupper/bin/Release/net8.0-windows/SysTrayGitBackupper.exe` (точный путь может совпадать с выводом сборки в вашей конфигурации).

Запуск из исходников без отдельной сборки:

```bash
dotnet run --project Src/SysTrayGitBackupper/SysTrayGitBackupper.csproj
```

## Тесты

```bash
dotnet test Src/SysTrayGitBackupper.sln
```

## Структура решения

| Проект | Назначение |
|--------|------------|
| `Src/SysTrayGitBackupper` | WPF-приложение: трей, UI, планировщик, настройки, сценарий бэкапа |
| `Src/NAN.Git` | Клиенты API провайдеров, модели репозиториев, фабрика клиентов, запуск Git |
| `Src/NAN.MaterialDesign.Components` | Переиспользуемые WPF-компоненты |
| `Src/NAN.MaterialDesignThemes.Orange` | Тема оформления (тёмная оранжевая) |

В приложении используются Prism, Material Design, Mapster, Serilog (лог в файл).

## Где хранятся настройки и лог

Файлы **`Settings.json`** и **`Log.txt`** создаются **в каталоге исполняемого файла** (рядом с `SysTrayGitBackupper.exe`).

**Важно:** ключи API (PAT, пароли приложений и т.п.) сохраняются в `Settings.json` в открытом виде. Ограничьте доступ к этому файлу и каталогу установки; не публикуйте настройки в открытых репозиториях.
